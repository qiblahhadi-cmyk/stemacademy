# Environment variables

Set these in `.env` for local work (git-ignored), or in Netlify's environment settings for hosted builds. Never commit values.

## Public (browser) configuration

Embedded in the browser bundle at build time. These identify the Firebase project and are not secrets, but they are still set per environment.

| Variable | Used by | Notes |
|---|---|---|
| `PUBLIC_FIREBASE_API_KEY` | `npm run build:client` | Live builds only. Required. |
| `PUBLIC_FIREBASE_AUTH_DOMAIN` | `npm run build:client` | Live builds only. Required. |
| `PUBLIC_FIREBASE_PROJECT_ID` | `npm run build:client` | Live builds only. Required. |
| `PUBLIC_FIREBASE_APP_ID` | `npm run build:client` | Live builds only. Required. |

Emulator builds (`npm run dev`, `build:client:emulator`) ignore these entirely and use demo values.

## Server (Netlify Functions, Firebase Admin)

| Variable | Used by | Notes |
|---|---|---|
| `FIREBASE_ADMIN_PROJECT_ID` | Functions, scripts | Project ID. Emulator mode requires a `demo-` ID. |
| `FIREBASE_AUTH_EMULATOR_HOST` | Functions, scripts, tests | Local only, e.g. `127.0.0.1:9099`. Presence switches to emulator mode. |
| `FIRESTORE_EMULATOR_HOST` | Functions, scripts, tests | Local only, e.g. `127.0.0.1:8080`. Both emulator hosts must be set together. |
| `FIREBASE_ADMIN_CLIENT_EMAIL` | Functions (live) | Service-account email. Secret. Live only. |
| `FIREBASE_ADMIN_PRIVATE_KEY` | Functions (live) | Service-account key. **Secret. Never commit. Never place in a browser bundle.** Live only. |

Configuration fails closed: if any emulator host is set without a `demo-` project, or a live configuration is incomplete, the server refuses to start.

## Application

| Variable | Used by | Notes |
|---|---|---|
| `APP_ENV` | Application | `development` locally. |
| `APP_BASE_URL` | Application | e.g. `http://localhost:8888` locally. |
| `APP_TIMEZONE` | Application | `Asia/Karachi`. Attendance and assessment dates are calendar dates in this zone. |

## Guarantees

- Emulator tooling refuses any project ID not starting with `demo-`, and refuses to run inside a Netlify build (`scripts/emulator-guard.mjs`).
- Client code never reads `FIREBASE_ADMIN_*` values.
- Passwords generated by the seed script are printed once and never written to disk.

## Controlled initial credential handoff

`scripts/issue-initial-credential.mjs` is an owner/technical-custodian utility. Emulator mode requires both emulator hosts and a `demo-` project. Non-emulator mode is guarded by `ALLOW_OWNER_ACCOUNT_ACTIVATION=true`, an exact `ACCOUNT_ACTIVATION_EXPECTED_PROJECT_ID` match, server-only `FIREBASE_ADMIN_*` credentials, an active administrator operator UID and `ACCOUNT_ACTIVATION_VERIFIED=true`. It refuses hosted Netlify execution. It displays a temporary password once in the terminal; never redirect or record that output. This script was not run against production in this phase.
